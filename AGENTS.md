# Wigum Gaming studio website

- Keep the site static. Edit `public/index.html` (English) and `public/no/index.html` (Bokmål) together; share styles and local artwork. Preview `public/` and check a narrow portrait and wide landscape viewport. Netlify publishes `main`; use `dev` for review.
- Add a game by copying `templates/game-entry.html` before the tools menu. This is a copyable HTML example, not a build-time template. Give each game unique IDs, its own screenshot/alt text, a short pitch, and direct links. Preserve the current studio colors, spacing, and language links.
- Keep platforms, controls, and estimated demand inside one collapsed native **Game details / Spilldetaljer** disclosure per game. Status and play links stay visible.
- **Platforms** in order: Browser, Android, iOS, Windows, macOS, Linux (Tux). Active means a public playable build/download exists; link to it. Gray means unavailable; give it a localized accessible label, no link. Browser play on iOS does not make an iOS download available.
- **Controls** in order: desktop, touch, gamepad. Desktop shows the minimum complete input scheme: `keyboard`, `mouse`, or `keyboard-mouse` when both are required. Gray the slot if unsupported; don't count partial menu navigation as gamepad play. Touch means playing on the touchscreen.
- **Stage:** use text and a colored dot: Pre-production (gray), Pre-alpha (violet; playable early work without numbered releases), In development (amber), Released (green). For numbered releases, display the game's deployed version beneath Play; don't hardcode a number from a tag. For pre-alpha, show the stage once.
- **Estimated hardware demand:** Low / Moderate / High, one to three filled segments with visible text. Judge the typical playable build (scene complexity, loading, and simulation); these are editorial estimates, not FPS guarantees or download sizes. Reassess after significant game changes.
- **Game sites:** the game repo owns its design, actual gameplay captures, Pages workflow, `/play/` export, and release label. Keep developer docs and source out of the public site artifact. Validate the public game and an input path before advertising browser support. The studio must not fetch project catalogs or require an API token.
